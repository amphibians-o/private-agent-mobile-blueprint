# 公開前チェック・アップロード対象

## 対象

リポジトリ名は `private-agent-mobile-blueprint`。非公式の設計集とオフライン画面例であり、完成サービスや他プロジェクトの公式品と名乗らない。

公開するのは公開候補ルートの `upload-manifest.json` にあるファイルだけ。隣のreview、認証/設定/ログ/バックアップ/元実装、検査中の一時ファイルを含めない。親ディレクトリ全体をGitへ追加しない。

## 初回公開の順序

1. READMEと仕様の内容を利用者が確認する。設計稿であることを明記する。
2. ライセンス、著作権表記、脆弱性報告窓口を決定する。未決のまま完成公開しない。
3. 許可リストだけを新しい空の公開候補へコピーする。既存実装のGit履歴を持ち込まない。
4. `python scripts/audit_public.py` と `python -B tests/test_audit_public.py` を実行する。
5. 別のsecret scannerと人による意味的監査を行う。実環境の画像・ZIP・一般のバイナリは公開対象外。例外はオフライン画面例から撮影し視認レビューしたPNGだけで、manifestの許可名とレビュー済みhashに限定する。
6. Gitを使う場合はステージ内容、全履歴のblob、ファイル名、コミットメッセージ、authorメールを検査する。本稿のスクリプトはGit履歴を検査しない。
7. 公開/非公開、アップロード先、タグ、配布条件を利用者が承認する。公開操作はその後。
8. リモートのexact treeを読戻し、ローカル配布物と照合する。公開確認は未認証で取得できるかを検査する。

公開された秘密は削除しても他者のclone等から取り戻せない可能性がある。資格情報の失効/ローテーションと履歴対処を分ける。[6]

## 検査スクリプトの範囲

検査する：許可リスト外ファイル、欠落、symlink、UTF-8以外、バイナリ、実ネットワーク識別子らしきもの、ユーザーディレクトリ/ドライブ絶対パス、よくある鍵形式、秘密付きURL、ローカル文書リンクの存在。

PNG例はsignatureとmanifestのhashだけを照合する。画像内の文字や意味の安全性は別の視認レビューで確認し、変更後は再レビューする。

検査しない：未知形式の秘密、人物/案件名の意味判定、実ネットワークACL、サーバー実装、OS権限、Git全履歴、GitHub Actionsログ/Release/Issue。スキャナーが0件でもこれらを済ませたことにしない。

追加ファイルは意図をレビューしてからmanifestに加える。検査を通すためだけに広い例外を作らない。エラー出力に秘密値自体を再表示せず、ファイル名/行/規則IDだけを示す。
