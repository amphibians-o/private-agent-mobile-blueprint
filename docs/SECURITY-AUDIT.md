# セキュリティ・便利さの設計監査（下書き）

監査対象：本リポジトリの設計とLLM構築依頼。完成サーバー、OS設定、ネットワークACLの実地検査ではない。以下の「必須」は提案仕様であり、既に実装・保証されたという意味ではない。

## 脅威モデル

保護対象は会話、ツール承認、成果物、内部接続資格、秘密ファイル、GPU処理、日常作業の可用性。攻撃者はURLを知る外部者、未承認の私設ネットワーク端末、紛失した認証済みスマホ、悪意あるWebページ、悪意ある会話/添付、依存パッケージの改ざんを想定する。

同じOSアカウントやバックエンドが既に完全侵害されている場合、アプリ認証・OS暗号化だけでは守れない。この限界を隠さない。ネットワークからの匿名閲覧防止と、認証済みスマホからのエージェント権限制御は別の目標である。

## 詳細判定

| ID / 重要度 | 危険・操作上の落とし穴 | 下書きで採る要件 | 受入確認 |
|---|---|---|---|
| SEC-01 / 最優先 | 隠したURLを認証の代わりにする | URLを知っていても未認証なら拒否。ネットワーク制限と端末認証を二重に置く | URL直入力、未認証GET/WS/メディア拒否 |
| SEC-02 / 最優先 | ドライブ全体やホームを静的配信 | 静的UIと私有状態と成果物領域を分離、任意パスAPI禁止 | traverse、絶対パス、リンク経由、秘密領域が拒否される |
| SEC-03 / 最優先 | 配信制限だけでagentのファイルアクセスも止まると誤認 | agentのOS/ツール権限も別途制限する | 境界外ファイルを指示してもツールから取得できない |
| SEC-04 / 最優先 | プロトタイプのHTTP Cookieを一般化 | HTTPS/WSSとSecure/HttpOnly/SameSite Cookie。ローカルHTTP例外は開発限定 | HTTPS以外の導入に安全完了を出さない |
| SEC-05 / 高 | 同じtailnetの全員に操作を許す | 利用者/端末/ポートを限定。アプリ認証を残す | 未承認のネットワーク端末から試験 |
| SEC-06 / 高 | CSRF、WebSocket乗っ取り | Host/Originの完全一致、変更操作CSRF、WS接続/各操作の認可 | 外部Origin、Origin欠落、不正CSRFを拒否 |
| SEC-07 / 高 | URLクエリ内の認証トークンがログに残る | 秘密をURLへ入れない。ブラウザWSはCookie+Origin、必要な確認は最初のフレームで期限付きに行う | 入口/アプリ/例外ログを検査。互換性で内部URLが不可避ならローカル限定・ログ抑止し制約を明記 |
| SEC-08 / 高 | バックエンドの任意RPCを公開 | メソッド、型、フィールド、scope、対象会話、owner世代を許可リストで検査 | 未知method、余計なfield、別profile、任意URLを拒否 |
| SEC-09 / 高 | 失効後も開いたWSで操作できる | WS各操作で認証再検査、失効時に対象端末の既存WSを閉じる | 接続済みのまま失効して操作拒否 |
| SEC-10 / 高 | 許可済み端末全体が同じ権限 | read-only / 会話操作 / 管理を分離、資源画面から停止不可 | read-only端末は送信/承認/引き継ぎ拒否 |
| SEC-11 / 高 | 短い接続コードの総当たり、再利用 | PC発行・短命・単回・原文保存なし・試行制限。端末別失効 | 期限切れ/二度目/並行消費/連続失敗を試す |
| SEC-12 / 高 | 監視のために万能SSH鍵を常設 | 監視専用権限、固定読み取り処理、転送/PTY制限、host key固定 | 任意コマンド・転送・別hostへの接続を拒否 |
| SEC-13 / 高 | ワーカーURL/コマンドをスマホから指定させる | ローカル登録済みaliasだけ。HTTPリダイレクト/別hostを拒否 | SSRF、DNS/接続先差替え、shell注入を拒否 |
| SEC-14 / 高 | 会話/ログ/HTMLを無検査で表示する | 文字として描画。MarkdownのHTML禁止、URL scheme制限、CSP、外部追跡画像の自動読込禁止 | script/イベント属性/悪意URL/外部画像を試す |
| SEC-15 / 高 | 添付ファイル・メディアIDから領域外や別会話に到達 | bytesだけ受け取る。サイズ/型/権限検査、会話紐づけ。ランダムIDは認可の代わりにしない | ID盗用、別会話、filename注入、拡張子偽装、Rangeを試す |
| SEC-16 / 高 | 内容/元パス/例外が診断やGitHubへ漏れる | 診断は許可された状態値と相関IDだけ。全文ログ/コマンドライン/パス/鍵を出さない | 故意の例外と失敗時ログも検査 |
| SEC-17 / 高 | 会話引き継ぎが進行中作業を不意に止める | 別確認、対象/端末/owner世代/期限束縛、正規終了→解放確認→再開 | owner差替え・失効・未解放時は中断 |
| SEC-18 / 中 | 更新が既存Desktop/GPU/WSを巻き込む | 中継だけ版固定更新、旧版へ戻せる。共有サービス停止を含めない | 候補版で検証し本owner不変確認 |
| SEC-19 / 中 | スマホ内の永続下書きが紛失時に残る | 一時保存既定、永続保存は明示。ログアウトの削除範囲を説明 | 再読込/ログアウト/ストレージ不可を試す |
| SEC-20 / 中 | Gitから消しただけで秘密が消えたと思う | 公開対象を新規組立、全履歴/添付/Actions/Releaseも監査。漏えい鍵は失効 | 現在ツリーだけでなく全blobとメッセージを検査 |

WSのOrigin、認証、失効、ログの推奨はOWASPを参照する。[4] 添付の型・サイズ・保存境界についてもOWASPを参照する。[5] GitHubは機密データ削除の前に資格情報の失効・ローテーションが必要になる点や、履歴削除の限界を説明している。[6]

## 運用上の便利さとの比較

| 便利さ | 安全側との衝突 | 採る折衷 |
|---|---|---|
| 一度つないだら毎回コード不要 | 紛失端末の長期アクセス | 端末一覧・期限・個別失効。重要操作は直前認証/再確認 |
| タップでGPU一覧 | 度重なるSSHとUI待ち | サーバー側短期キャッシュ・並列化・タイムアウト。最後の成功時刻を表示 |
| 通信復旧で自動再接続 | prompt重複実行 | 読み取り再取得だけ自動。送信不確定は履歴確認・明示再送 |
| 動画をすぐ再生 | 大きいファイルのキャッシュとID転用 | 認証付きRange、転送量制限、private/no-store、会話認可 |
| 同じ会話をPC/スマホで共有 | 別ownerの競合/承認対象混同 | 保存ID/実行ID/owner世代を照合、古い応答を破棄 |
| リロード後も入力が残る | スマホ内に秘密が残る | 一時保存と任意の永続保存、消去導線 |
| どんな構成でも自動導入 | 秘密探索と権限拡大 | 能力だけ質問、未対応は停止、設定値はローカル入力 |

## 残余リスクと公開判定

- セキュリティ設計をLLMへ渡しても、生成実装が要件を満たすとは限らない。否定試験と実機受入が必要。
- OSの秘密保管は同一ユーザーからの侵害を防ぐ万能境界ではない。
- 監視専用SSHの制約は対象OSとOpenSSH版で実試験する。制約未確認なら「監視専用」と名乗らない。
- 本稿のスキャナーは有限のパターン検査。未知形式の鍵、個人名、画像内文字、意味的漏えい、外部サービス設定を保証しない。
- **設計下書きとしてレビュー可能。稼働サービスの安全完了・監査認証として公開しない。** MITライセンスと非公開の報告方法はLICENSE / SECURITY.mdを参照。個別環境への導入・継続サポートは保証しない。
